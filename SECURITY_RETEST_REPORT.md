# VoiceCastTTS v2 — remediation and retest

Date: 2026-10-26. Baseline: source `80a01477b33da5167082a77e876d847a6f13c964`, with functional baseline `4119c50`. This report supersedes the unresolved application/runtime status in the historical SECURITY_REVIEW_REPORT.md. The remediation commit is recorded in Git history and the local checkpoint.

## Result

The reproduced application findings have fixes and regression evidence. V2 now uses a project-private patched Python runtime, authenticated local API/media access, browser-origin checks and bounded request/response/project/cache handling. Existing functional behavior, including real local speech, early listening and MCP handoff, passed the final suites. This is an application remediation/retest result, not an independent penetration-test certificate or a public/binary-release approval.

## Final validation

- **593 Python tests passed** in 141.495 seconds. The 15 security/refusal/retention tests are included. Launcher checks were additionally rerun after the final private-base guard; positive/negative startup checks used a stubbed server and opened no production app.
- **24 JavaScript checks passed.**
- **176 Chrome tests ran: 174 passed, two optional real-AI-service checks skipped**, in 184.203 seconds. Includes real local Kokoro speech and early-listening playback. Separate actual-Chrome security checks passed for session startup, XSS containment, oversized-project refusal, cross-origin preview refusal and CORS.
- Initial Chrome import/MCP failures were missing credentials in the test fixture, corrected without weakening enforcement. The affected 22-test suite passed and then the final complete browser suite passed. Failed and passing logs remain local.
- Fresh hash-enforced offline runtime-only installation/imports and dependency checks passed. Sampled project/private-runtime/session-parent Windows ACLs had zero broad Everyone/Authenticated Users/Users allow entries. No other-user interactive login test was performed.

## Privacy and publishing

Settings, personal/custom voices, generated output, runtime/environment files, browser profiles, session credentials, raw test evidence, handoffs and backups are ignored and excluded from the intended source publication. GitHub is a source backup, not a complete asset backup. The source uses clean publishing snapshots with a public GitHub no-reply identity, excluding inherited development history. `scripts/check_publication.py` checks the entire proposed publishing history for private-file categories, credential patterns, personal Windows paths and private commit-email metadata before upload. It reports counts, not matched secret values; it is a bounded check and cannot recognize every possible kind of private content.

The access credential inherits the private project-folder Windows permissions. Same-user/administrator code that can read those files, inspect process/browser memory or replace application code is outside this HTTP boundary. A virtual environment/private runtime is not an operating-system sandbox. The URL fragment is removed during bootstrap, but this is not a promise to erase OS/process/browser crash artifacts; dedicated profile and all such local artifacts stay excluded from GitHub.

## Remaining scope and release decision

- Full native/transitive license-text/notice completeness and model/voice redistribution permission must be checked for any binary redistribution. DEPENDENCY_INVENTORY.md is metadata evidence, not legal clearance. No binary/model/voice distribution is being published here.
- Unknown/legacy unmarked spools and owner exports are not automatically erased. UI Clear does not erase all local caches, browser data, rollback backups or exported files. This deliberately avoids deleting unknown/user-owned data.
- No destructive load test, public-network exposure test, native fuzzing, other-user login test, global OS/certificate audit or independent external penetration test was performed. The default service remains loopback-only; keep the project folder private.
- Optional external AI-service checks were skipped. LM Studio/MCP synthetic integration and ordinary browser/local TTS are covered; actual owner listening acceptance remains a separate quality decision.
- Reassess these boundaries after new imports, externally supplied audio, voice cloning, remote access or a runtime/dependency upgrade. Other feature work remains deferred.

Application/runtime remediation is ready for owner use and review. A public-release/security sign-off is a separate explicit decision; this report does not grant it.
